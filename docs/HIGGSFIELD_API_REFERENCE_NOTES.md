# Higgsfield API integration notes (official docs, 2026-10-04)

- [How the API works](https://docs.higgsfield.ai/docs/how-to/introduction): base URL `https://api.higgsfield.ai`; submit JSON, persist `request_id`, poll returned `status_url` or receive a webhook, download output only on `completed`.
- [Open Higgsfield quick start](https://open.higgsfield.ai/quick-start): The owner copies one complete credential from [Open Higgsfield API keys](https://open.higgsfield.ai/api-keys). Store the unchanged value in the **server-only** `HF_API_KEY` environment variable. For REST calls use `Authorization: Key ${HF_API_KEY}` and the `https://api.higgsfield.ai` base URL. Never use Bearer, split, trim, assemble, log or expose the credential in frontend code, URLs or source. The older [authentication page](https://docs.higgsfield.ai/docs/authentication) still describes an ID/secret pair; for this CRM use the owner's current Open Higgsfield single-key contract instead. Invalid credentials return HTTP 401.
- [Polling](https://docs.higgsfield.ai/docs/concepts/polling): start around 2 seconds and back off to 10 seconds with jitter. Terminal states: `completed`, `failed`, `nsfw`, `canceled`. HTTP 401 requires credential correction; 404 requires ID/account verification; 5xx/network failures may retry the status request, **not generation submission**.
- [Model catalog](https://docs.higgsfield.ai/docs/models): per-model generation endpoints and schemas vary. Select a documented **image-to-video model** that accepts an OpenAI keyframe and outputs 9:16 motion; do not substitute another footage vendor for Higgsfield.
- Read-only connector activation and workspace selection are separate from production CRM API credentials. The server still requires `HF_API_KEY` through secure project secrets, a per-clip cost preflight, bounded task persistence, poll/webhook recovery, quality gates and tests before enabling a weekly run.
