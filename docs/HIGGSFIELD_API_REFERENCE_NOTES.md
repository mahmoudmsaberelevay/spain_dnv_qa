# Higgsfield API integration notes (official docs, 2026-10-04)

- [How the API works](https://docs.higgsfield.ai/docs/how-to/introduction): base URL `https://api.higgsfield.ai`; submit JSON, persist `request_id`, poll returned `status_url` or receive a webhook, download output only on `completed`.
- [Open Higgsfield quick start](https://open.higgsfield.ai/quick-start): The owner copies one complete credential from [Open Higgsfield API keys](https://open.higgsfield.ai/api-keys). Store the unchanged value in the **server-only** `HF_API_KEY` environment variable. For REST calls use `Authorization: Key ${HF_API_KEY}` and the `https://api.higgsfield.ai` base URL. Never use Bearer, split, trim, assemble, log or expose the credential in frontend code, URLs or source. The older [authentication page](https://docs.higgsfield.ai/docs/authentication) still describes an ID/secret pair; for this CRM use the owner's current Open Higgsfield single-key contract instead. Invalid credentials return HTTP 401.
- [Polling](https://docs.higgsfield.ai/docs/concepts/polling): start around 2 seconds and back off to 10 seconds with jitter. Terminal states: `completed`, `failed`, `nsfw`, `canceled`. HTTP 401 requires credential correction; 404 requires ID/account verification; 5xx/network failures may retry the status request, **not generation submission**.
- [Model catalog](https://docs.higgsfield.ai/docs/models): per-model generation endpoints and schemas vary. Select a documented **image-to-video model** that accepts an OpenAI keyframe and outputs 9:16 motion; do not substitute another footage vendor for Higgsfield.
- Read-only connector activation and workspace selection are separate from production CRM API credentials. The server still requires `HF_API_KEY` through secure project secrets, a per-clip cost preflight, bounded task persistence, poll/webhook recovery, quality gates and tests before enabling a weekly run.

## Candidate clip model and non-generative cost check (2026-10-04)

- The owner's master requires **four 5-second clips + a 3-second white logo outro for each reel**. The [Kling 2.5 Turbo Standard image-to-video API](https://docs.higgsfield.ai/docs/models/kling-2-5-turbo/standard-image-to-video) documents a 5-second image-to-video request. An authenticated **estimate-only** request for one illustrative 5-second clip returned USD **0.179** (no media was generated). Four such clips would quote USD **0.716**, conservatively rounded to USD **0.72**; OpenAI keyframes, internal ELEVAY voice, QA retries and assembly must fit the **remaining USD 0.78** within the existing USD 1.50/item and combined USD 100 Cairo-month controls. Never authorize the paid submission from a static rate: re-estimate the exact real clip inputs and reserve all components before work.
- An explicit-vertical alternative, [Wan 3.0 Prime image-to-video](https://docs.higgsfield.ai/docs/models/wan-3-prime/image-to-video), supports `aspect_ratio: "9:16"` and `generate_audio: false`. Account **estimates only**, not billed generation: 1080p five seconds quoted USD **1.190** (four clips USD **4.76**); 720p five seconds USD **0.595** (four USD **2.38**); 480p five seconds USD **0.289** (four USD **1.156**, leaving USD **0.344** for keyframes/voice/assembly but requiring material upscaling). Both 720p and 1080p exceed the USD 1.50/item cap **before** keyframes. No option is cleared for paid production; the cheaper Kling candidate's native 9:16 result and premium 1080×1920 export QC remain unverified.
- `server/higgsfieldClipPreflight.ts` is a **non-generative quote-only helper**, not a dispatch service. It uses the unchanged single key, rejects malformed quotes and clip-only cap breaches, and does not create a budget reservation. The model docs do **not** expose an explicit 9:16 or silent-audio parameter; vertical-frame output, 1080×1920 upscale quality and audio stripping require genuine clip QA before any production release. Source-image provenance and request ownership, durable idempotency, current pricing, cancellation and account generation access remain unverified. Do not submit paid clips or enable the legacy Manus media workflow on the basis of these estimates.
- A separate `higgsfieldClipTechnicalQa` gate now requires a playable **native 9:16, silent, five-second** video at a minimum 720×1280 source resolution. It refuses landscape/stretching, 480p input, native audio and incorrect duration. The metadata gate is unit-tested; **no actual Higgsfield result has passed it**. Technical validity is not creative approval: every person must still pass head-to-toe frame review (formal shoes, clothing and accessory continuity, anatomy, shadows, motion) and the final composite needs voice/logo/export inspection before a preview can be called ready.
- The official [OpenAI image-generation guide](https://platform.openai.com/docs/guides/image-generation) currently recommends the Image API with `gpt-image-2.5-sunburst` for precision or `gpt-image-2.5-flare` for faster everyday generation, and says image-generation responses include `usage` for real token accounting. Neither keyframe model was generated or priced against this ELEVAY account in this milestone. A future four-keyframe reservation must account for input and image-output tokens **before** any paid call and reconcile response usage; do not assume the older built-in image helper proves a direct OpenAI output or fits the remaining per-item cap.
- Official-source preparation now has a separate, **read-only** `marketingOfficialCitationVerifier` that fetches only exact allowlisted HTTPS authority hosts, rejects redirects and credentialed URLs, limits page size, verifies that the proposed evidence quote literally appears in the fetched HTML, and returns the page hash/time with `publicationAuthority: false`. This is a safety primitive, **not** a live news researcher or source-quality judgment. Persisting citations per news-led item, reputable-domain review, fact validation and release-gate integration remain pending; the old internal-only planner remains paused.
