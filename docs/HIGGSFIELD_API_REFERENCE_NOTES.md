# Higgsfield API integration notes (official docs, 2026-10-04)

- [How the API works](https://docs.higgsfield.ai/docs/how-to/introduction): base URL `https://api.higgsfield.ai`; submit JSON, persist `request_id`, poll returned `status_url` or receive a webhook, download output only on `completed`.
- [Open Higgsfield quick start](https://open.higgsfield.ai/quick-start): The owner copies one complete credential from [Open Higgsfield API keys](https://open.higgsfield.ai/api-keys). Store the unchanged value in the **server-only** `HF_API_KEY` environment variable. For REST calls use `Authorization: Key ${HF_API_KEY}` and the `https://api.higgsfield.ai` base URL. Never use Bearer, split, trim, assemble, log or expose the credential in frontend code, URLs or source. The older [authentication page](https://docs.higgsfield.ai/docs/authentication) still describes an ID/secret pair; for this CRM use the owner's current Open Higgsfield single-key contract instead. Invalid credentials return HTTP 401.
- [Polling](https://docs.higgsfield.ai/docs/concepts/polling): start around 2 seconds and back off to 10 seconds with jitter. Terminal states: `completed`, `failed`, `nsfw`, `canceled`. HTTP 401 requires credential correction; 404 requires ID/account verification. A failed status GET may retry with backoff. A timed-out generation submission may only be replayed with the **same persisted idempotency key and identical body**, never a fresh paid request.
- [Model catalog](https://docs.higgsfield.ai/docs/models): per-model generation endpoints and schemas vary. Select a documented **image-to-video model** that accepts an OpenAI keyframe and outputs 9:16 motion; do not substitute another footage vendor for Higgsfield.
- Read-only connector activation and workspace selection are separate from production CRM API credentials. The server still requires `HF_API_KEY` through secure project secrets, a per-clip cost preflight, bounded task persistence, poll/webhook recovery, quality gates and tests before enabling a weekly run.

## Candidate clip model and non-generative cost check (2026-10-04)

- The official [Kling 2.5 Turbo Standard API](https://docs.higgsfield.ai/docs/models/kling-2-5-turbo/standard-image-to-video) confirms `POST https://api.higgsfield.ai/kling-video/v2.5-turbo/standard/image-to-video` with `prompt`, public `image_url`, and `duration: 5`. No `aspect_ratio` or audio setting is documented. A successful enqueue returns `request_id`, `status_url`, and `cancel_url`; [status](https://docs.higgsfield.ai/docs/api-reference/requests/get-request-status.md) exposes `video.url` only upon completion. A queued request can be canceled via the returned `cancel_url`; once processing starts, cancellation may fail. The [idempotency contract](https://docs.higgsfield.ai/docs/concepts/idempotency) supports one persisted `Idempotency-Key` per clip: replay an identical request with the **same** key after an ambiguous timeout; changed arguments return HTTP 422. This documents a safe future design, **not** an authorized production submitter.
- `server/higgsfieldClipRequestContract.ts` now implements **pure, non-networking** request/receipt/status validators for that documented model, including one immutable clip idempotency key, same-request UUID and trusted status/cancel URLs, a five-second body, no undocumented aspect/audio fields, and a completed-video URL check. It deliberately cannot send a POST, reserve money or approve a result. Unit tests cover malformed URLs, mismatched task IDs and missing media. Durable reservation and request ownership, exact real quotes, controlled upload and head-to-toe output QC remain prerequisites before attaching any network submission function.
- [Official file uploads](https://docs.higgsfield.ai/docs/concepts/file-uploads.md) can mint a short-lived `upload_url` and `public_url` from `POST /files/generate-upload-url`; the upload PUT must use the returned `upload_headers` and never forward the Higgsfield key to presigned storage. Preserve a private original keyframe record and avoid putting credentials or client data in the public URL. The [account estimate](https://docs.higgsfield.ai/docs/concepts/billing-and-retention.md) pattern is documented, but the exact Kling estimate path is not explicitly stated on the model page. A read-only account-specific quote was obtained for illustrative parameters; this empirical result must not replace quoting real inputs at dispatch time.
